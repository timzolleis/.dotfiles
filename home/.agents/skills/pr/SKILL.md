# Pull Request

Create or update a PR for the current branch.

## Step 1: Analyze

Run these commands to understand the full scope of changes:

```bash
git status
git log --oneline origin/main..HEAD
git diff origin/main...HEAD --stat
```

Review ALL commits since diverging from main — the PR covers the entire branch, not just the latest commit.

## Step 2: Determine Create vs Update

```bash
gh pr view --json number,title,body 2>/dev/null
```

- If a PR exists: **update** title/body with `gh pr edit`
- If no PR exists: **create** a new one

## Step 3: Draft Title

- Max 60 characters
- Imperative mood, lowercase after prefix
- No period at the end
- Format: `<what changed>` — clear and concise

**Good:** `Remove unused spass package`, `Add student export endpoint`
**Bad:** `Updated stuff`, `PR for feature`, `fix: some changes`

## Step 4: Draft Body

Use this exact template:

```markdown
## Summary

<2-5 bullet points describing WHAT changed and WHY>

## Changes

| Area | Detail |
|------|--------|
| `path/or/scope` | What changed there |
| ... | ... |
```

### Rules for the body

- **Summary** bullets: start with a verb (Add, Remove, Fix, Refactor, Update)
- **Changes table**: group by logical area (package, module, config), not by file
- Keep it scannable — no paragraphs, no filler text
- Do NOT include a test plan section unless the user asks for it
- Do NOT include "Generated by" footers

## Step 5: Create or Update

### Create (new branch + PR)

```bash
git checkout -b <branch-name>  # if not already on a feature branch
git push -u origin <branch-name>
gh pr create --title "<title>" --body "$(cat <<'EOF'
<body>
EOF
)"
```

**Branch naming:** `<type>/<short-description>` (e.g., `chore/remove-spass`, `feat/student-export`)

### Update (existing PR)

```bash
gh pr edit --title "<title>" --body "$(cat <<'EOF'
<body>
EOF
)"
```

## Step 6: Output

Print the PR URL when done.

## Constraints

- NEVER push to `main` directly — always use a feature branch
- NEVER force-push without asking the user first
- If on `main`, create a new branch before pushing
- Use HEREDOC for the body to preserve formatting
